# 用户交互呈现规范（跨路由共享）

> 本文是 SKILL.md「调用约定」中用户交互呈现的唯一事实来源。各流程只定义"何时必须停下来问用户"，"如何呈现内容与收集确认"一律按本文执行。

## 1. 内容全走正文

用户必看的任何内容——授权 URL、写操作预览全文、示例值、背景说明——先以**回复正文**完整呈现，再发起提问：

- `ask_user` 的 question 只写问句本身；options 只写选项 label
- URL 一律放正文（可点击跳转），不进 question，也不进 description（description 在部分客户端不渲染）
- 预览表格、多行文本、超过一句话的内容均放正文，不进 question

完成判据（可检验）：

1. 必看内容已完整出现在正文
2. question 中不含 URL、表格、多行或超过一句的内容
3. 涉及写操作或授权时，已获得用户明确回应

## 2. 确认门槛不因工具缺席而降低

| 宿主环境 | 做法 |
|---------|------|
| 有 `ask_user` | 用它收集确认/选择；question 简短，内容已在正文 |
| 没有 `ask_user` | 正文呈现内容后，等用户下一条消息明确回应；未获回应不推进 |

**工具可缺席，确认门槛不可降**：写操作未获用户明确确认不执行；授权未获用户完成不继续；不因缺少交互工具而跳过任何确认环节。

## 3. 呈现顺序

内容多时按"正文在前、提问在后"排列，URL 与关键内容置于正文末段、紧邻提问，保证用户读到问题时内容仍在视野内。修改循环：用户提出修改 → 更新内容 → 重新按本文呈现 → 再次收集回应。

需要向用户呈现或确认的场景，呈现方式一律按 §1-§3 执行，各流程文件不另行复述：
