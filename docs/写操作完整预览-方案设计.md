## 一、需求

1. 写操作执行前给用户**完整预期预览**并允许修改，取代现状「执行完才能在平台看到真实结果」。
2. 预览必须是**全字段级**：update 呈现「完整任务 现状→执行后」对照（而非仅变更字段）；create 呈现全部字段含未提供字段的默认值/（空），让用户能发现任何不合适的字段并修改。

用户已确认的三个决策：

| 决策点 | 结论 |
|--------|------|
| 实现载体 | 纯提示词模板（只改文档，预览由 agent 按模板合成） |
| 覆盖范围 | 全部写操作（任务 + 周报 + free-mode 透传） |
| 免确认例外 | 无例外，一律预览 |

## 二、整体流程

```
写操作请求
   ↓
① 取现状：实时 get_task_detail / get_weekly_report_detail
   ↓
② 合成完整预览：模板 U（变更：全字段 现状→执行后）/ 模板 C（创建：全字段含默认值）
   ↓
③ ask_user 呈现（完整预览放 question 正文）
   ↓  用户修改 → 更新参数 → 回到②重新合成完整预览
④ 明确确认 → 执行写入（--args-file）
   ↓
⑤ 回读核验：get detail 逐字段对照预览，回执带核验结论
```

## 四、关键设计

### 模板 U（变更类：update_task / delete_task / assign_task / update_weekly_report / 提交）

| 字段 | 现状 | 执行后 |
|------|------|--------|
| 全字段 | 实时 detail | 现状平移，仅本次修改字段变化并加粗标注「本次修改」 |

- MCP 英文枚举翻译为中文呈现（completed→已完成），写入参数保持英文枚举
- delete：执行后列整体标注「软删除，平台不可见」
- assign：执行人呈现完整新名单，被移除者显式标注（覆盖式）
- 大文本（description 等）全量呈现，不截断

### 模板 C（创建类：create_task / add_task_log / create_weekly_report / batch_create）

| 字段 | 将写入的值 |
|------|-----------|
| 全字段 | 用户提供的值；未提供的字段显式标注平台默认值或（空），不留白 |

- create_task 默认：状态=未开始、进度=0%、urgency 未给=normal（优先级=中）、无执行人
- 周报默认：is_submitted=0（草稿），用户明确说「提交」才出现 0→1 变更

### 硬性规则

1. 无例外：任何写操作（含单字段低危、用户说「直接做」）执行前先完整预览
2. 现状一律实时 detail 获取（完成判据：现状列每个值都来自本次 detail 返回）
3. 预览完成判据：覆盖对象全部用户可见字段且每字段有执行后的值
4. 确认完成判据：用户对最终版预览明确回应确认/执行；期间任何修改都重新合成完整预览
5. 执行完成判据：回读 detail 与预览逐字段一致；不一致立即报告差异
6. 批量写：逐条完整预览（每条一个区块），确认后逐条执行、逐条独立报告
7. ask_user 呈现时完整预览放 question 正文（历史教训：description 可能被 UI 隐藏）

### 边界情况

| 场景 | 处理 |
|------|------|
| 现状列数据疑误 | 说明现状不可在预览中修改，引导用户到平台修正后再操作 |
| detail 拉取失败 | 中止预览（凭记忆合成会让完整预期失真），按 failure-modes 报错 |
| 用户预览后放弃 | 不执行，如实报告未做任何写入 |
| free-mode 透传写工具 | 同样走完整预览，按工具语义判断读写性质 |
