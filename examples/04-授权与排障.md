# 案例：授权与排障

> 路由：setup / auth（工作流细节见 `references/_shared/setup-flow.md`、`auth-flow.md`）

## 场景

第一次使用时的授权长什么样、授权过期了怎么重授、怀疑配置或连接有问题时怎么自查。

## 你可以这样说

- 「配置 iwp」（首次配置）
- 「诊断 iwp」（体检配置、授权、连通性）
- 「重新授权」/「授权过期了」
- 「更新 iwp 技能」（更新本身，见下）

## agent 会做什么

1. **首次配置**：以模板为底稿创建 `.env` 并安装依赖；唯一需要你确认的是 MCP server 地址，其余用默认值。
2. **首次授权 / 重新授权**：
   - agent 发起授权并**自动打开浏览器**（没能弹出时会把授权链接发在对话里，点击即可）；
   - 你在浏览器登录 IWP 并确认授权，**回到对话即可**——agent 以本地回调到达为准自动推进，不需要你再说「我授权好了」；
   - 授权完成后 agent 播报结果。
3. **诊断**：「诊断 iwp」会做一轮聚合体检（依赖、`.env`、授权状态、MCP 连通性），逐项给出结论与处置建议。
4. **更新技能**：说「更新 iwp 技能」即可，`.env` 与授权凭证自动备份并恢复，更新后**新会话**生效。

## 你会看到什么

- 对话里的授权链接（可直接点击）+ 浏览器中的 IWP 授权确认页。
- 授权完成的播报。
- 体检结果清单（每项 通过 / 异常 + 建议）。

## 常见变化与注意点

- **授权窗口 5 分钟**：超时后 agent 会主动问你是否重新发起，说「重新授权」即可重来。
- 端口 9999 被占用时授权会显式报错并提示占用进程，处理后重试即可。
- IWP 网页端的「退出登录」不影响 MCP 授权；要彻底下线就说「撤销 iwp 授权」。
- 排障细节见 `references/_shared/auth-flow.md`、`references/_shared/failure-modes.md`；更新细节见 `references/_shared/update-flow.md`。
