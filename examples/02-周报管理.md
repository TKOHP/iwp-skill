# 案例：周报管理

> 路由：reports（工作流细节见 `references/reports/README.md`）

## 场景

写周报、交周报、查周报。最有代表性的用法：让 agent 读取你本周的课题任务，自动起草周报。

## 你可以这样说

- 「根据我本周的任务生成周报」/「按课题任务写周报」
- 「帮我写本周周报」（手动提供内容）
- 「批量提交本周所有周报」
- 「查我的周报」/「这周谁还没交」
- 「把周报 45 的成果部分改成……」

## agent 会做什么

1. **按任务自动生成**：
   - 先获取当前工作周和你的身份信息，再拉取你本周的任务（必要时翻任务日志补细节）；
   - 按课题聚合成若干条周报（每条 = 事项名 + 做了什么 + 产出/进度）；
   - **逐条给你全字段预览**——任务到周报的映射是 agent 生成的，必须你过目，防止把没做完的事写成成果；
   - 你确认后才创建，默认存为**草稿**；你明确说「提交」才会提交。
2. **手动创建**：你不给素材时 agent 会先问你，不会编造工作内容。
3. **批量创建**：逐条预览、逐条确认；执行时单条失败不影响其余，事后逐条报告成功/失败。
4. **查询与修改**：可按人、按周、按课题、按提交状态查；修改前同样预览确认。

## 你会看到什么

- 周报列表：表格（ID / 周 / 事项 / 提交状态）。
- 创建前：逐条全字段预览区块。
- 创建后：回执（周报 ID + 提交状态）。

## 常见变化与注意点

- **默认草稿，不自动提交**——明确说「提交」才会置为已提交。
- 本周没有任务时，agent 会如实说明并问你要素材，不会硬编。
- 提示「无进行中工作周」时，需要你先到 IWP Web 端创建本周工作周。
- 命令与参数细节以 `cli.py tools` 输出为准，见 `references/reports/README.md`。
